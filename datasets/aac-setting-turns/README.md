# AAC Setting Turns

Short parent-question / child-answer turns for augmentative and alternative communication (AAC), labelled by
**where the conversation happens**. Each answer is written the way a child actually produces one on a picture
board: one to four separate cards, not a sentence.

```json
{"setting": "play", "question": "What do you want to do?", "cards": ["blocks", "build", "tower"]}
```

## Why it exists

AAC dialogue corpora are overwhelmingly domestic. In the corpus this dataset was built to repair, 88% of
training states were home or unlabelled, leaving play at 1.2%, school at 1.1% and the doctor's at 0.9%. A model
trained on it learns that the setting token carries no information. Asked "What do you want to do?" at play,
ours ranked *coffee* 10th and *a ball* 2396th.

The missing knowledge is the ordinary association between a place and the things that happen there. We looked
for it in the data first and it is not there:

| Source of the association | Result |
|---|---|
| Pointwise mutual information over setting-labelled rows | fails: *football* → transport, *book* → doctor; *ball*, *swing*, *lego*, *homework* have zero occurrences |
| Sentence-embedding similarity to the setting's own mined questions | works for content-rich questions (selfcare, restaurant), fails for generic ones (play, doctor) |
| Sentence-embedding similarity between vocabulary folders and settings | reliable only for the top few (food → restaurant); noise below that (toys → restaurant, sports → school) |

So the turns are generated by a large language model, which does hold that association, and released here so the
step is inspectable and reusable rather than buried in a training script.

## How it was made

`model/data/gen_setting_data.py` prompts a model through the Claude Code CLI (`claude -p`), once per batch of
turns per setting. Each prompt is seeded with the real, corpus-mined partner questions for that setting from
`web-client/public/questions.json`, so the questions stay close to what partners actually ask, and asks for
concrete setting-specific answers with generic filler ("good", "yes", "thanks") excluded.

Generation is resumable: each row records the batch that produced it, and re-running tops up to the requested
count rather than starting over.

## Limitations, and what this dataset is not

- **It is model-generated, not observed.** These are plausible turns, not recordings of real AAC users. It is
  suitable for teaching a model which vocabulary belongs to which setting. It is not evidence about how
  children with complex communication needs actually talk, and it should not be used to make claims about them.
- **It carries the generating model's cultural assumptions** about school, mealtimes, play and clinics. Expect
  a Western, English-speaking, broadly middle-class default.
- **The answers are idealised.** Real AAC output includes misfires, abandoned turns, perseveration and
  telegraphic fragments that this data does not contain.
- **No real people are represented.** No user data, transcripts or personal information were used to produce it.
- Downstream, only answer words that map onto an existing card in the board vocabulary survive; the rest are
  dropped. Coverage per setting is recorded in `stats.json`.
